# Старт у світі, польовий планшет і рукавиці

Нотатки для команди українською. Усе, що бачить гравець, англійською.

Основа: робоче дерево Codex станом на 14.11 ~13:00. Перший коміт гілки `intro-tablet` — точний знімок цього дерева, другий — ці зміни. `missions.js`, `simulation.js`, `opportunity.js` і карта Місяця **не змінені**.

## Що змінилося для гравця

1. **Перший кадр — місячна база на все вікно** (без прокручування) і компактна картка з кнопкою **Start Training**.
2. **Start Training** — астронавт піднімає планшет, на екрані розминка про гірлянду й радіо. Ті самі два рішення («What would you do?» і «Why?»), та сама оцінка 0–2 (`baseline`), без підказок.
3. **Begin Moon Mission** (активна після двох відповідей) — планшет опускається, камера там же, світ одразу інтерактивний.
4. **HUD під час місії:** назва місії, номер ходу, коротке попередження (прогноз ходу), рядок «Selected: …» і кнопка **Tablet T**. Внизу підказка: `WASD to move · Hold LMB to look · Click a module to pick it · T for tablet`.
5. **Бюджет, модулі, прогноз батареї, Run Shift, результат ходу («What changed last shift»), підказка Earth, джерело NASA** — тепер на планшеті. Після Run Shift планшет лишається в руках і показує, що змінилося.
6. **Кінець місії**, питання Earth про захід сонця, Next Mission / Retry і фінальний екран з оцінками й домашньою вправою — теж на планшеті, поверх 3D-сцени.

## Керування

| Дія | Як |
| --- | --- |
| Ходьба | WASD відносно погляду (зіткнення карти без змін) |
| Огляд | **Лише поки затиснута ЛКМ** у сцені. Без кнопки рух миші камеру не крутить. Pointer lock прибрано |
| Клік / перетягування | Поріг **6 CSS px**: менше — клік (вибір модуля під курсором), більше — поворот камери без вибору |
| Клавіатура | Стрілки — огляд, **E** або Enter — вибір модуля в центрі (крапка-приціл) |
| Планшет | **T** або кнопка HUD — підняти/опустити. **Esc** або **Back to Base** — опустити |
| Скидання | Відкриття планшета, втрата фокуса вікна чи сцени, `pointercancel`, `lostpointercapture` скидають ЛКМ і затиснуті клавіші. Після закриття фокус повертається в сцену |

Поки планшет піднятий, ходьба, огляд і кліки в сцені вимкнені. Позиція й напрямок камери не змінюються після відкриття, закриття та Run Shift: сцена більше **не перемонтовується** на кожну дію.

### Модель планшета

- Одиниці — **метри**. Корпус 0,30 × 0,205 × 0,03 м. Екран **0,252 × 0,158 м** (≈16:10), заглиблений на 3 мм.
- Осі `tabletRoot`: +x праворуч, +y вгору, **+z до глядача** (нормаль екрана). Початок координат — центр пристрою.
- Вузли:
  - `tabletRoot` — увесь пристрій;
  - `device` — корпус і екран (у портреті повернутий на 90°);
  - `screenAnchor` — центр поверхні екрана; `userData.size = { width, height }` у метрах для поточної орієнтації;
  - `gripLeft` / `gripRight` — середини лівого й правого країв; локальна +x дивиться назовні (лівий віддзеркалений `scale.x = -1`).
- Деталі: світлий корпус, гумові кути (обідок), ребриста гума на боках, велика помаранчева кнопка живлення й ребристий регулятор зверху (під рукавиці), табличка FIELD UNIT 01, ремінь ззаду.
- Вузьке вікно (співвідношення сторін < 0,95): планшет повертається в портрет, щоб екран був вужчим, але вищим. На 420 px екран має 320 × 510 px.

### Стани й анімація

`down → raising → up → lowering → down`.
- Рух: **300 мс** (крива ease-in-out cubic); при `prefers-reduced-motion` — **110 мс** без нахилу.
- Повторне натискання посеред руху розвертає анімацію з поточної точки. Будь-яка серія швидких T закінчується в останньому запитаному стані (перевірено: 3 натискання → up, ще 3 → down).
- Події `vm.on('opened' | 'closed' | 'state', cb)`.
- HTML-екран з'являється лише в стані `up` (fade 120 мс) і щокадру підганяється під `screenRect()` (розбіжність ≤ 2 px за тестом).

### Рукавиці

Матові світлі рукавиці. Великі пальці лежать на боковій рамці (не на екрані), решта пальців — за пристроєм; темні накладки на пальцях; манжета з помаранчевою смугою. Передпліччя з трьома сегментами-кільцями тягнуться від манжети до ліктя за нижнім кутом кадру й перебудовуються щокадру. Рукавиці є дочірніми вузлами `gripLeft` / `gripRight`.

## Контролер сцени

```js
const view = mountScene(container, mission, shift, selected, onSelect, pose, { onFrame });
view.setShift(n);            // світло й сонячні панелі для ходу n, без перемонтування
view.setInputEnabled(bool);  // ходьба, огляд, кліки
view.viewmodel;              // open() / close() / toggle() / state / screenRect() / on()
view.focus();                // повернути фокус у сцену
view.stop();                 // звільнити все (зміна місії або Retry)
```

`main.js` монтує сцену **один раз на місію** (Start, Retry, Next Mission). HTML-шар — `createTabletUI(viewEl, view.viewmodel, { onClosed })`, сторінки рендеряться в `tablet.content`.

## Як підключити (Codex)

Гілка зроблена поверх його робочого дерева, тому найпростіше накласти патч:

```bash
git apply --ignore-whitespace intro-tablet.patch   # файли в робочому дереві з CRLF, патч з LF
npm install && npm run build
```

Або взяти гілку: `git fetch origin intro-tablet` і `git diff a68df71 origin/intro-tablet -- src scripts docs/intro-tablet.md | git apply --ignore-whitespace`. Патч перевірено: він чисто накладається на копію робочого дерева Codex, після чого `vite build` проходить.

Якщо після 13:00 Codex змінював `main.js`, `scene.js` чи `style.css`, перенесіть вручну:
- `src/fp/*` — нові файли, конфліктів немає;
- у `scene.js`: прибрати pointer lock, додати блок «Look only while the left button is held», рендер шару «в руках» після світу (`autoClear = false`, `clearDepth`) і повернення контролера;
- у `main.js`: сцену не перемонтовувати в `render()`, а сторінки планшета рендерити в `tablet.content`.

Пакет-лок я перегенерував (`npm install`). Залежності ті самі: `three ^0.187`, `vite ^8.3.8`.

## Що перевірено

`npm run build` проходить. `python3 scripts/check_intro.py` у headless Chrome із програмним WebGL (SwiftShader) — **35/35**, зокрема:
- сцена на все вікно без прокручування; Start Training; ходьба до старту вимкнена;
- HTML-екран збігається з 3D-екраном; Begin лише після двох відповідей; оцінка 0–2;
- камера на місці після Begin, фокус повертається в сцену;
- рух миші без кнопки не крутить камеру; ЛКМ + рух крутить; відпустив — зупинилася;
- клік < 6 px по Life Support вибирає модуль; перетягування з модуля не вибирає;
- WASD; ходьба вимкнена з піднятим планшетом; Esc; швидкі T;
- вибір у 3D видно на планшеті; після Run Shift та сама canvas і та сама позиція; Moon виграється; Next Mission → Mars;
- Back to Base повертає фокус; blur вікна відпускає клавіші;
- вузьке вікно 420 px (портрет, екран 320 px); reduced motion; помилок у консолі немає.

**Не перевірено:** вбудований браузер Codex і ноутбук із GPU.

## Ручна перевірка у вбудованому браузері Codex (5 хв)

1. Перший кадр: база, Земля, картка Start Training, сторінка не прокручується.
2. Start Training → планшет піднімається знизу з рукавицями; на екрані питання про гірлянду й радіо.
3. Begin Moon Mission → планшет опускається, видно HUD і підказку.
4. Затиснути ЛКМ у сцені й вести мишею → камера крутиться; відпустити → стоїть. Просто водити мишею → нічого.
5. Короткий клік по табличці LIFE SUPPORT → кільце «Selected» і рядок «Selected: Life Support». Перетягування з таблички → поворот без вибору.
6. T → Run Shift на планшеті → «What changed last shift»; Esc → камера там же.
7. Швидко натиснути T 5 разів → планшет повністю піднятий, не завис посередині.
8. Звузити вікно до ~420 px → планшет у портреті, кнопки читаються.
9. Якщо у вбудованому браузері ЛКМ «залипає» після виходу курсора за вікно — це перехоплює `pointermove` з `buttons === 0`; повідомте, якщо ні.

## Відкладено

Торс і черевики при погляді вниз, легке похитування рук під час ходьби, пальці, що рухаються, звук піднімання планшета.
